# ダミー参加者の一括運転

1つのNode.jsプロセスで1～50名のWebSocket接続を維持する。ブラウザ、参加者ごとのOSプロセス、ポーリングは使わない。受信Snapshotから自分の回答資格・ラウンド・停止状態だけを取り出し、他参加者の画像や名簿を保持しない。描画は8種類のPNGと操作履歴を共有し、各ラウンドのランダムなタイミングで回答を確定する。

## 本番の専用認証

Workerの任意Secret `DUMMY_ACCESS_SECRET` をローカルの管理者用JSONファイルにも保存する。Git、ブラウザ、URL、ログには含めない。CLIはルームに束縛された有効期限1時間のHMAC署名トークンをHTTPヘッダーで送信する。再接続時にはトークンを更新する。秘密鍵を持つ管理者だけが発行でき、Secretの変更・削除ですべて失効する。

通常の試用コードとは別の資格情報。指定ルームへの参加・再接続・状態取得・回答・退出だけを許可し、ルーム作成は許可しない。参加者名や公開クエリによる免除はない。参加者本人のCookieと最新WebSocketの操作権チェックは維持する。

署名を検証できた通信だけ、TrialGateの1分間のjoin/refresh/command制限を免除する。日次API予算、R2読み書き予算、IP上限、ルーム定員、リクエストサイズ制限、限定公開停止は維持する。無料枠を無制限に使える仕組みではない。

例（プロジェクト直下から、秘密値ではなくファイルパスを渡す）:

```powershell
pnpm dummy:fleet 4L7ATX 25 https://webflipper.shojoradi-pages.workers.dev C:/Users/silve/Documents/WebFlipper/apps/worker/.wrangler/trial-secrets.json
```

ローカルFakeサーバーならSecret不要:

```powershell
pnpm dummy:fleet ABC234 50 http://127.0.0.1:8787
```

## 保存・停止・復帰

参加直後にセッションを原子的に保存してからWebSocketを開く。同じセッションファイルの二重起動はlockファイルで拒否する。再起動時は保存Cookieを再利用し、同じ名前で新規参加しない。保存先はルーム・接続先別の無視対象 `output/dummy/`。第5引数で絶対パスを指定できる。

接続失敗・切断は他クライアントへ波及させず、65秒待ち・直列で再接続する。HTTP 429にはRetry-Afterに従う。10秒ごとに要求人数、実接続人数、失敗数、RSSメモリを表示する。Ctrl+C/SIGTERMで退出し、ルーム終了時は全接続を閉じて自動終了する。強制終了後にlockが残った場合はPIDが存在しないことを確認してからlockだけを取り除く。

## 検証

`pnpm test`はFake通信Adapterで50接続と単独切断復帰を確認する。署名の改ざん・期限切れ・別ルーム・鍵変更を拒否し、免除後も日次予算と通常参加者の制限を守ることを確認する。

`node scripts/check-dummy-fleet.mjs`はCloudflareへ接続せず、ローカルFakeサーバーに実際の50接続を張り、サーバー名簿、PNG付き回答50件、セッション保存50件、ルーム終了による正常停止を確認する。所要時間とRSSを出力する。試験用ポート8899を使用する。

2026-11-11のWindows実測では、単一Node.jsプロセス・ブラウザ0個で50接続が751ms、全50名がPNG回答を確定し、報告時のRSSは82MiB。これはクライアント側の測定であり、本番Workerが50名の負荷を保証する測定ではない。CIにも同じFakeサーバーによる実接続試験を追加した。

導入時のRedはFleet未実装、署名付き専用認証が403になること、50回の状態取得が10回制限で失敗することを確認した。実装後は96件の単体・Adapterテスト、50名実接続試験、通常の限定試用ブラウザテストが成功。本番では既存25名の識別情報を維持して専用認証へ切り替え、25接続・失敗0を確認した。

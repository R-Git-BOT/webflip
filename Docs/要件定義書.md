## 2. プロジェクト概要

### 2.1 背景

複数人でお題に対して回答する遊びやイベントでは、紙のフリップ、ホワイトボード、チャット、口頭回答などを使うことが多い。

しかし、オンラインまたはブラウザ上で実施する場合、次の課題がある。

* 参加者全員の回答を同じ形式で集めにくい
* 手書き回答のような直感的な入力がしにくい
* ホストが回答受付、回答確認、正解選択、結果表示を一連の流れとして管理しにくい
* 参加者に「今何をすればよいか」が伝わりにくい
* チャットやビデオ会議ツールだけでは、回答受付から結果表示までの進行管理がしにくい

本システムは、Webブラウザ上で「お題提示」「参加者の手書き回答」「ホストによる正解選択」「結果表示」を行えるようにするフリップ回答ツールである。

### 2.2 目的

ホストが作成したルームに参加者がURLから参加し、ホストが毎ラウンド入力したお題に対して、参加者がCanvas上で手書き回答を行う。ホストは回答一覧を確認して正解を選択し、全員に結果を表示できるようにする。

### 2.3 達成したいゴール

* ホストがルームを作成できる
* ホストが回答制限時間を設定できる
* 参加者がURLからルームに参加できる
* 参加者がCanvasに手書き回答を入力できる
* 参加者が回答を送信できる
* ホストが回答一覧を確認できる
* ホストが正解回答を1つ以上選択できる
* 結果表示時、正解回答を赤背景で表示できる
* ホストが次ラウンドへ進行できる
* ホストがルームを終了できる
* ルーム終了時に関連データを削除できる
* ホスト切断時、5分以内であれば復帰して進行を継続できる
* MVP段階では、ログイン・スコア機能・ランキングなしで基本的な進行が成立する

## 5. 業務要件

### 5.1 利用フロー

1. ホストがWebアプリにアクセスする
2. ホストがルームを作成する
3. ホストが回答制限時間を設定する
4. ホストが参加用URLを参加者へ共有する
5. 参加者がURLからルームにアクセスする
6. 参加者が表示名を入力して参加する
7. ホストが参加者一覧を確認する
8. ホストが毎ラウンドごとにお題を入力する
9. ホストが回答受付を開始する
10. 参加者がCanvasに手書き回答を入力する
11. 参加者が回答を送信する
12. 制限時間終了またはホスト操作により回答受付を終了する
13. ホストが回答一覧を確認する
14. ホストが正解回答を1つ以上選択する
15. ホストが結果を公開する
16. 参加者が結果を確認する
17. ホストが次ラウンドへ進む、またはルームを終了する
18. ルーム終了後、関連データを削除する

### 5.2 業務ルール

* 1ルームにつきホストは1名とする
* 1ルームあたりの非ホスト参加者は最大12名とする
* 1ルームの最大人数は、ホスト1名 + 参加者12名の合計13名とする
* 同時稼働ルーム数は最大3ルームを想定する
* 参加者はルームURLから参加する
* 参加者は表示名を入力して参加する
* ホストは毎ラウンドごとにお題を入力する
* 参加者は1ラウンドにつき1つの回答を送信できる
* 回答送信後、参加者は原則として回答を編集できない
* 正解は1つ以上選択できる
* 複数正解を許可する
* 正解未選択では結果公開できない
* 結果表示では正解回答を赤背景で表示する
* 結果表示では赤枠や「正解」ラベルを表示しない
* 不正解回答は通常背景で表示する
* 回答表示順は固定しない
* スコア機能はMVPに含めない
* ルームが閉じられた場合、ルームに紐づくデータは削除する

### 5.3 ホスト切断時の業務ルール

* ホストの切断を検知しても即座にルームを閉じない
* ホスト切断後、5分間は復帰を待つ
* ホストが5分以内に復帰した場合、ルームを継続する
* ホスト復帰後、切断前の状態から問題なく進行できるようにする
* ホスト不在中に制限時間終了などの状態変更条件を満たした場合、その状態変更は保留する
* 参加者にはホスト復帰待ちであることを表示する
* ホストが5分以内に復帰しない場合、ルームを閉じる
* ルームを閉じた後、ルームに紐づくデータを削除する

### 6.1 機能一覧

| 機能ID | 機能名       | 概要                       | 優先度 |
| ---- | --------- | ------------------------ | --- |
| F001 | ルーム作成機能   | ホストが新しいルームを作成する          | 高   |
| F002 | ルーム設定機能   | ホストが制限時間などを設定する          | 高   |
| F003 | ルーム参加機能   | 参加者がURLからルームに参加する        | 高   |
| F004 | 参加者一覧表示機能 | ホストが参加者の状況を確認する          | 高   |
| F005 | お題入力・表示機能 | ホストが毎ラウンドお題を入力し、参加者に表示する | 高   |
| F006 | 回答入力機能    | 参加者がCanvasに手書き回答を入力する    | 高   |
| F007 | 回答送信機能    | 参加者が回答を送信する              | 高   |
| F008 | 回答一覧確認機能  | ホストが送信済み回答を確認する          | 高   |
| F009 | 正解選択機能    | ホストが正解回答を選択する            | 高   |
| F010 | 結果表示機能    | 正解回答を参加者に表示する            | 高   |
| F011 | 次ラウンド開始機能 | ホストが次のお題へ進める             | 中   |
| F012 | ルーム終了機能   | ホストがルームを終了する             | 高   |
| F013 | 状態同期機能    | ホスト・参加者間で現在状態を同期する       | 高   |
| F014 | ホスト切断復帰機能 | ホスト切断時に5分間復帰を待つ          | 高   |
| F015 | データ削除機能   | ルーム終了後に関連データを削除する        | 高   |
| F016 | エラー表示機能   | 不正操作や通信失敗を利用者に表示する       | 高   |

### 6.2 主要機能詳細

#### F001. ルーム作成機能

* ホストは新しいルームを作成できる
* ルーム作成後、参加用URLを発行する
* ルーム作成者をホストとして扱う
* ホスト用識別情報を発行する

#### F002. ルーム設定機能

* ホストは回答制限時間を設定できる
* 非ホスト参加者上限は12名とする
* MVP段階では、スコアや高度なゲーム設定は扱わない

#### F003. ルーム参加機能

* 参加者はURLからルームに参加できる
* 参加者は表示名を入力する
* 非ホスト参加者が12名に達している場合、新規参加を拒否する
* 終了済みルームには参加できない

#### F005. お題入力・表示機能

* ホストは毎ラウンドごとにお題を入力する
* 入力されたお題は参加者の回答画面に表示される
* お題の事前登録やテンプレート機能はMVP対象外とする

#### F006. 回答入力機能

* 参加者はCanvasに手書きで回答できる
* 回答はPNG dataURLとして扱う
* 描画、全消し、送信ができる
* 空のCanvasは送信不可とする
* 回答送信後は編集不可とする

#### F009. 正解選択機能

* ホストは送信済み回答一覧から正解を選択できる
* 正解は1つ以上選択できる
* 複数正解を許可する
* 正解未選択では結果公開できない

#### F010. 結果表示機能

* ホストと参加者に結果を表示する
* 正解回答は赤背景で表示する
* 赤枠は表示しない
* 「正解」ラベルは表示しない
* 不正解回答は通常背景で表示する
* 回答表示順は固定しない

#### F014. ホスト切断復帰機能

* ホスト切断を検知した場合、5分間復帰を待つ
* 5分以内に復帰した場合、ルームを継続する
* 5分以内に復帰しない場合、ルームを閉じる
* ホスト不在中は状態変更を保留する
* 参加者にはホスト復帰待ちの状態を表示する

#### F015. データ削除機能

* ルーム終了時、ルームに紐づくデータを削除する
* ホスト未復帰によりルームを閉じた場合も同様にデータを削除する
* 長期保存は行わない

## 7. 画面要件

| 画面ID | 画面名        | 利用者     | 概要                    |
| ---- | ---------- | ------- | --------------------- |
| S001 | トップ画面      | ホスト     | ルーム作成を開始する            |
| S002 | ルーム作成・設定画面 | ホスト     | ホスト名、制限時間などを設定する      |
| S003 | 参加画面       | 参加者     | 表示名を入力して参加する          |
| S004 | 待機画面       | ホスト・参加者 | 参加者待機・開始待ちを表示する       |
| S005 | お題入力画面     | ホスト     | 毎ラウンドのお題を入力する         |
| S006 | 回答入力画面     | 参加者     | Canvasに回答を入力する        |
| S007 | ホスト進行画面    | ホスト     | 回答状況を確認する             |
| S008 | 正解選択画面     | ホスト     | 回答一覧から正解を選択する         |
| S009 | 正解選択中画面    | 参加者     | ホストが正解選択中であることを表示する   |
| S010 | 結果表示画面     | ホスト・参加者 | 正解回答を赤背景で表示する         |
| S011 | ホスト復帰待ち画面  | 参加者     | ホスト切断中であることを表示する      |
| S012 | エラー画面      | ホスト・参加者 | ルーム不存在、満員、終了済みなどを表示する |

### 7.1 画面方針

* 参加者画面では「今何をすればよいか」を最優先で表示する
* ホスト画面では「現在の状態」「回答状況」「次にできる操作」を明確に表示する
* Canvas領域はスマートフォンでも描きやすいサイズを確保する
* 結果表示では、正解回答を赤背景で示す以外の装飾を追加しない
* ホスト不在中は、参加者に復帰待ちであることを明示する
* ルーム内の画面切り替えは、ページ全体のリロードを見せないSPA的な体験にする

| データ名        | 内容                                | 保存要否   |
| ----------- | --------------------------------- | ------ |
| ルーム情報       | ルーム識別情報、状態、作成日時など                 | 要      |

* 回答履歴表示はMVP対象外とする

## 10. 非機能要件

### 10.1 ユーザビリティ

* 参加者が説明なしでも現在の操作を理解できる画面にする
* 回答中、回答済み、正解選択中、結果表示中、ホスト復帰待ちを明確に示す
* スマートフォンのタッチ操作に配慮する
* Canvasの全消し、送信操作を分かりやすくする

### 10.2 規模

| 項目              | 要件         |
| --------------- | ---------- |
| 1ルームあたりホスト数     | 1名         |
| 1ルームあたり非ホスト参加者数 | 最大12名      |
| 1ルームあたり最大人数     | 13名        |
| 同時ルーム数          | 最大3ルーム想定   |
| 同時接続人数          | 最大39名程度を想定 |
| 1回の利用時間         | 数分〜1時間程度   |

### 10.3 性能

* 参加者の回答送信後、ホスト画面に速やかに反映されること
* ホストの状態変更後、参加者画面に速やかに反映されること
* 最大3ルーム、各ルーム参加者12名程度で基本進行に支障がないこと
* Canvas回答データが過大にならないようサイズ上限を設けること

### 10.4 セキュリティ

* IPA「安全なウェブサイトの作り方」のセキュリティ実装チェックリストにおいて、未対策項目がないこと
* ルームIDは推測されにくい値にする
* ホスト操作はホストのみが実行できるようにする
* 参加者がホスト権限の操作を実行できないようにする
* 入力値は画面表示時に適切にエスケープする
* XSS、CSRF、SQLインジェクション、OSコマンドインジェクション、ディレクトリトラバーサル、HTTPヘッダインジェクション、クリックジャッキング、アクセス制御不備等への対策を行う
* Canvas回答データにはサイズ上限を設ける
* 不正な連続操作や過大なリクエストに対して最低限の制限を行う
* ログインなしで利用するため、ルームURLを知っている人は参加できる前提とする
* URL流出による第三者参加はMVP段階の制約として扱う

### 10.5 稼働環境

| 項目      | 要件                               |
| ------- | -------------------------------- |
| 開発端末    | Windows PC                       |
| 開発接続    | SSH                              |
| 開発エディタ  | VS Code Remote - SSH             |
| 実行環境    | SSH接続可能なLinuxサーバー                |
| PCブラウザ  | Chrome、Edge、Safari、Firefoxの最新版付近 |
| スマートフォン | iOS Safari、Android Chrome        |
| 通信環境    | インターネット接続が必要                     |
| デプロイ先   | 自分のLinuxサーバー                     |
| サーバ運用   | 小規模運用を前提とする                      |

## 11. 状態要件

### 11.1 ルーム状態

| 状態      | 内容              | ホスト表示        | 参加者表示      |
| ------- | --------------- | ------------ | ---------- |
| 待機中     | 参加者の参加を待つ       | 参加者一覧、開始操作   | 開始待ち       |
| お題入力中   | ホストがお題を入力する     | お題入力画面       | お題入力待ち     |
| 回答中     | 参加者が回答する        | 回答状況確認       | Canvas回答画面 |
| 正解選択中   | ホストが回答を確認し正解を選ぶ | 正解選択画面       | 正解選択中表示    |
| 結果表示中   | 正解結果を表示する       | 結果画面、次ラウンド操作 | 結果画面       |
| ホスト復帰待ち | ホストが切断し復帰を待つ    | 復帰時に元状態へ戻る   | ホスト復帰待ち表示  |
| 終了済み    | ルームが終了した        | 終了表示         | 終了表示       |

### 11.2 基本状態遷移

```text
待機中
  ↓
お題入力中
  ↓
回答中
  ↓
正解選択中
  ↓
結果表示中
  ↓
お題入力中 または 終了済み
```

### 11.3 ホスト切断時状態遷移

```text
任意の進行状態
  ↓ ホスト切断
ホスト復帰待ち
  ↓ 5分以内に復帰
切断前の状態へ復帰
  ↓ 5分以内に復帰しない
終了済み
  ↓
関連データ削除
```

## 12. システム実現案

### 12.1 技術スタック

| 領域       | 採用技術                                    |
| -------- | --------------------------------------- |

| 画面遷移     | Next.js Router                          |

### 12.2 設計モデル

* ルーム進行は状態機械モデルで扱う
* Route HandlerやSocketイベント処理は薄くし、業務ルールはService層・Domain層に寄せる

## 13. 受入条件

* ホストがルームを作成できる
* ホストが制限時間を設定できる
* 参加者がURLからルームに参加できる
* 非ホスト参加者が最大12名に制限される
* 同時3ルーム程度で基本進行できる
* ホストが毎ラウンドお題を入力できる
* 参加者がCanvasに手書き回答を入力できる
* 回答はPNG dataURLとして保存される
* 空Canvasを送信できない
* 参加者が回答を送信できる
* ホストが回答一覧を確認できる
* ホストが正解を1つ以上選択できる
* 正解選択中、参加者には正解選択中であることが表示される
* 結果表示時、正解回答は赤背景で表示される
* 結果表示時、赤枠や正解ラベルが表示されない
* ホストが5分以内に復帰した場合、進行を継続できる
* ホストが5分以内に復帰しない場合、ルームが閉じられる
* ルーム終了時に関連データが削除される
* スコア機能が実装されていない
* IPA「安全なウェブサイトの作り方」のチェックリストに未対策項目がない
* Linuxサーバー上で起動・利用できる

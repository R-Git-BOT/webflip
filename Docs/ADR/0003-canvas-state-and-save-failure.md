# ADR 0003: Canvas状態と保存障害時の扱い

- Status: Accepted
- Date: 2026-10-02

## Context

Canvasは、回答受付中の再編集、Undo・Redo、再接続後の復元に対応する必要がある。同時に、確定済み回答や切断中に時間切れとなった回答を、すべてのクライアントへ同じ見た目で提示する必要がある。

PNG画像だけではUndo・Redo履歴を復元できず、描画操作履歴だけでは表示側に再描画処理が必要になる。また、下書き保存に失敗したまま一部の参加者だけが描画を続けると、失われる回答量と利用可能時間に差が生じる。

## Decision

- 下書きと確定回答は、描画操作履歴と1024×768の不透明PNG画像の組で保存する。
- 描画操作履歴を再編集、Undo・Redo、再接続の復元に使い、PNG画像を正解選択と結果表示に使う。
- 自動保存時と回答確定時の両方で、描画操作履歴とPNG画像を保存する。
- 回答確定は、サーバーが両方を保存して確定コマンドを受理した時点で成立する。
- 自動保存が3秒以上失敗した場合は、ルーム全体の回答受付、タイマー、Canvasを一時停止する。
- 保存機能が1分以内に復旧すれば保存済み状態から再開し、復旧しなければルームを終了する。
- サーバーは描画操作履歴、PNG形式、画像サイズ、データ量を検証し、仕様上限を超える入力を拒否する。

## Consequences

- 再接続後もUndo・Redoを含む編集状態を復元できる。
- 判定・結果画面は描画実装に依存せず、統一されたPNG画像を表示できる。
- 同じ下書きを2形式で保持するため、R2の使用量、書き込み回数、自動保存時の通信量が増える。
- 保存障害が1人に発生した場合でもルーム全体が停止するため、進行は遅れるが参加者間の公平性を維持できる。
- 保存障害が1分継続すると、復旧を待ち続けずルームが終了する。

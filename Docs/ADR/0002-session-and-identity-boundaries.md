# ADR 0002: セッションと本人識別の境界

- Status: Accepted
- Date: 2026-10-02

## Context

WebFlipperは匿名参加とDiscord参加の両方を許可し、同じ参加者としての再接続も扱う。ルームコードは共有しやすい識別子であり、ホスト権限や参加者本人を証明する秘密情報ではない。

秘密情報をURLやJavaScriptから読み取れる保存領域へ置くと、意図しない共有やスクリプトによる窃取の影響が大きくなる。また、同じ本人が複数のタブや端末から同時操作すると、Canvasや回答確定が競合する。

## Decision

- ホストと参加者の秘密情報はURLやlocalStorageへ保存せず、`HttpOnly`、`Secure`、`SameSite`属性を設定したCookieで保持する。
- ルームコードとDiscordユーザーIDは秘密情報として扱わず、それだけではホスト・参加者の操作を許可しない。
- Discord OAuthでは `identify` だけを要求し、本人情報の取得後にアクセストークンを破棄する。
- ルーム中に保持するDiscord情報はユーザーID、表示名、アバター情報に限定する。
- 1つの本人識別情報につき操作可能な接続は1つとし、後から接続したタブまたは端末へ操作権を移す。
- ルーム終了時にサーバー側セッションを失効させ、Cookieと一時的なDiscord情報を削除する。
- ルーム作成とルームコード入力には、IPアドレス単位の設定可能な試行回数制限を適用する。

## Consequences

- 参加URLを共有してもホスト権限は共有されない。
- JavaScriptからセッション秘密情報を直接読み取れないため、XSS発生時の影響を抑えられる。
- 匿名参加者がブラウザデータを削除すると同一人物として復帰できない。
- 匿名参加者が別のブラウザ識別情報を作ることによる除外回避は、MVPでは完全には防げない。
- 新しいタブや端末へ操作権を移すと、以前の画面では操作できなくなる。
- IPアドレスを共有するネットワークでは複数利用者が同じ試行制限を共有する可能性があるため、制限値は運用設定で調整できる必要がある。

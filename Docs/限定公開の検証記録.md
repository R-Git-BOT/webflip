# 限定公開の検証記録

2026-11-10

## RedからGreenへ確認した振る舞い

- 公開ルーム識別子からホスト用セッションを推測できたため、秘密のセッションIDを独立したランダム値に変更した。
- 保存済みデータの読み込み失敗時に例外が漏れたため、HTTP 503の制御された応答へ変更した。
- ホスト切断が重なると保存障害の終了期限が5分まで延びていたため、保存障害の1分期限を優先するよう変更した。
- 試用コード入力後のローカルフォーム送信がOrigin検証で拒否されたため、フォームページのReferrer-Policyをsame-originへ修正した。
- 3秒継続した保存失敗による停止と、復帰後の残り時間の維持をFake保存Adapterで確認した。
- R2を読み込めないコールド状態で終了できなかったため、保存メタデータから終了・削除できる経路を追加した。
- 失効済みセッションの読み込みが404になっていたため、Cookieを失効させて空のセッションへ戻すよう変更した。
- WebSocketへの不要なメッセージが無視されて接続が残ったため、4008で切断するよう変更した。
- PNG形式・展開後サイズ・不透明性、メタデータ確定失敗時の旧回答の保全、コマンド重複送信、保存キャッシュ、試用コードの改変と期限を確認した。

## 未検証・対象外

- 20ルーム・合計100人の負荷保証。現在の公開は同時1ルーム・定員最大50人。定員の受付検証と、50人が描画し続ける実環境の負荷検証は区別する。
- 長時間運用と実環境での保存障害注入、Cloudflare全体障害時の削除完了時間。
- 正式対応する全ブラウザ・全端末での検証。
- Discord OAuth、CIからの自動デプロイ、7日間のログ保持保証。
- 外部攻撃や、同一Cloudflareアカウントの他用途も含めた課金ゼロの絶対保証。

## 定員50人への変更確認

2026-11-10の追加指示により、プルダウンを10〜50人の5人刻みに変更。APIで20人以上が400になること、旧選択肢が画面に残ること、50回答の配置が5列10行になることをRedで確認してから修正した。

Fake RoomStoreを使うAPIテストでは、50人の参加を受理し、51人目を満員で拒否し、50回答が一斉提出されることを確認する。ブラウザでは50人を選んだルーム作成と、50回答のPC（1440×1000）・スマートフォン（390×844）表示を確認する。50人の実回線同時描画と、本番環境での長時間負荷は未検証。日次予算は人数にかかわらず共通で適用する。

変更後の型検査と単体・統合テスト81件は成功。標準のブラウザテスト4件、ローカルWranglerでの4件、試用コード付きフロー1件も成功した。画面表示テストでは外部ブラウザプラグインを使わず、リポジトリ既存のPlaywrightとHTTP/WebSocketのFake応答を使用した。

## 参加用QRコード

参加URL直下にブラウザ内で生成するQRコードを追加。クリックするとネイティブdialogで拡大表示する。閉じるボタン・Escape・背景クリックで閉じ、元のボタンへフォーカスを戻す。

PC（1440×1000）・スマートフォン（390×844）のFakeルームで、QRボタンが存在しないRedを確認してから実装した。縮小版・拡大版のSVGを画像として読み取り、デコード結果が表示中の参加URLと一致することを確認する。外部QR生成サービスへURLを送らず、ホストの認証情報や試用コードをQRに含めない。

型検査・単体/統合テスト81件・標準E2E6件・ローカルWrangler E2E6件・限定試用E2E1件が成功。実機カメラの読み取り試験と全対応ブラウザでの確認は未実施。

## 待機画面の固定と切断者の一括除外

2026-11-10追加指示: ダミークライアントを全停止し、PCの共有パネルをstickyに、参加者名簿を独立スクロールに変更。高さ720pxでもQRまで表示されるよう、パネル内の余白と文字サイズを画面高に合わせる。スマートフォンは縦積みレイアウトで名簿内をスクロールする。

ホストの個別除外と「切断中の参加者を一括除外」を接続し、確認キャンセル時は送信しない。一括対象はコマンド処理時に実際のWebSocketから照合し、復帰済み参加者を残す。除外したセッションを失効させ、同じ識別情報による再参加を拒否する。匿名識別情報を削除しての参加まで防げる機能ではない。

参加API成功後にWebSocket接続が成立しなかった参加者が接続中のまま残る問題も修正。ルーム再表示時に実接続と照合し、変更がある場合だけ保存する。

Redは、参加者による一括除外が拒否されないこと、APIがコマンドを受理しないこと、名簿が全体スクロールになること、高さ720pxでQRが隠れることをそれぞれ確認した。Fake RoomStoreと接続集合、50人のFakeルームで、接続者の保全・除外後の失効・再読込時の接続補正を検証。PC 1440×1000 / 1280×720、モバイル390×844でスクロール位置と確認操作を検証する。

実際のブラウザ接続を閉じてから一括除外するE2Eを追加したところ、CIでローカルFakeサーバーが切断状態を反映しないことを検出した。WebSocketの接続・切断時にRoom Serviceと名簿配信を更新し、同じE2Eの成功を確認した。本番用Workerの接続処理とは別のローカルAdapterの修正。

## 終了後のルーム再作成

終了画面には再作成の導線がなく、終了済みセッションを5分間復元していた。終了画面にホスト用の「新しいルームを作る」と参加者用の「トップへ戻る」を追加。自分の終了済みセッションだけを解除し、ルーム・参加者Cookieを失効させて、招待URLのクエリを除いたトップへ戻す。終了画面の保持期間は他の参加者に対して維持する。

Runtimeでは終了後もホストの離脱が拒否されるRed、APIではCookieが消えないRed、ブラウザでは再作成ボタンがないRedをそれぞれ確認して修正。終了→再読み込み→トップ→再読み込み→別ルーム作成、他参加者の終了表示保全、招待URLからトップへの復帰を検証する。通常の進行中ルームでのホスト退出は引き続き拒否し、終了済みルームの離脱だけはWebSocketの再接続完了を待たずに受け付ける。

検証中、停止した購読の遅延close通知が新しい接続を「未接続」に上書きする競合も検出した。Fake WebSocketでRedを確認し、停止済み購読のopen・message・closeを無視し、購読停止時に接続状態を解除するよう修正した。
